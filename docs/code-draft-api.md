# 작성 중인 풀이 코드 저장·복원 API

로그인 회원의 문제별·언어별 코드를 서버 DB에 저장한다. 자동 저장 타이머와 편집기 복원은 프론트에서 구현해야 한다. 서버 저장 성공 이후에는 같은 계정으로 다른 기기에서 접속해도 코드를 불러올 수 있다.

## 인증·경로

모든 요청에 `Authorization: Bearer <accessToken>`을 넣는다. 회원 ID는 토큰에서 결정하며 URL·본문에 넣지 않는다. 관리자도 다른 회원의 코드를 가져올 수 없다.

`/api/code-drafts/{problemId}/{language}`

- problemId: 양수 문제 ID.
- language: `C`, `CPP`, `JAVA`, `CSHARP`, `JAVASCRIPT`, `PYTHON` 중 하나. 대문자 enum 이름을 그대로 사용한다.
- 문제집·채점 API와 별개이며 실행·제출이 저장을 대신하지 않는다.

## 저장

`PUT /api/code-drafts/123/JAVA`

```json
{"code":"class Main {\n    public static void main(String[] args) {}\n}"}
```

- 해당 회원·문제·언어의 기록이 없으면 `201 Created`와 같은 경로의 `Location` 헤더.
- 이미 있으면 `200 OK`. 항상 코드 전체를 보낸다.
- code는 필수 문자열이며 최대 102400자(Java 문자열 길이 기준, 보충 문자는 두 글자로 계산). 빈 문자열·공백·탭·줄바꿈을 그대로 저장한다.
- 성공 본문은 GET과 같다. `updatedAt`은 서버의 마지막 내용 변경 시각이며 프로젝트의 다른 시각과 동일한 LocalDateTime 형식이다. 같은 내용을 다시 보내면 시각은 유지될 수 있다.

## 복원

`GET /api/code-drafts/123/JAVA`

```json
{
  "problemId": 123,
  "language": "JAVA",
  "code": "class Main {}",
  "updatedAt": "2026-11-04T14:00:00"
}
```

아직 저장한 적이 없으면 `200`과 다음 본문이다.

```json
{"problemId":123,"language":"JAVA","code":"","updatedAt":null}
```

**기본 코드 템플릿은 `updatedAt`이 null일 때만 적용한다.** 사용자가 코드를 모두 지워 저장한 경우에도 code는 빈 문자열이지만 updatedAt은 있으므로, 이때 템플릿을 다시 덮어쓰지 않는다.

## 자동 저장 흐름

1. 로그인 계정·문제·언어를 편집 세션의 키로 잡고 GET을 보낸다. 복원 완료 전에는 편집기를 읽기 전용으로 두는 방식이 가장 단순하다. 조회 실패를 빈 코드로 취급해 자동 저장하지 않는다.
2. 응답이 현재 편집 세션의 것인지 확인한 뒤 코드를 적용한다. 문제·언어 전환 전의 늦은 응답은 무시한다. 복원 전 편집을 허용한다면 요청 이후 사용자가 수정했을 때 응답으로 그 내용을 덮어쓰지 않는다.
3. 입력할 때마다 미저장 표시를 하고, 2초 타이머를 다시 시작한다. 입력이 2초 동안 없으면 현재 코드 전체를 PUT으로 보낸다.
4. 같은 세션의 저장 요청은 **한 번에 하나만** 보낸다. 요청 중 입력이 바뀌면 최신 내용을 대기시키고 앞 요청 종료 후 전송한다. 응답이 도착해도 현재 편집기 내용과 그 요청의 코드가 다르면 저장 완료 표시를 하지 않는다.
5. 문제·언어 전환 시 이전 세션의 최신 코드를 큐에 넣고, 경로·코드·계정을 요청 당시 값으로 고정한다. 다시 그 세션을 불러올 때는 해당 큐의 저장이 끝난 뒤 GET한다.
6. 저장 실패 시 편집 내용을 유지하고 실패 표시와 재시도 동작을 제공한다. 실패한 저장보다 앞선 서버 코드를 GET해 편집기에 덮어쓰지 않는다.
7. 로그아웃·계정 변경 시 이전 계정의 타이머와 큐를 정리한다. 이전 세션 코드를 새 계정의 토큰으로 저장하지 않는다. 토큰 만료 시에는 입력을 유지하고 재로그인을 안내한다.

여러 탭·기기가 같은 문제·언어를 동시에 편집하면 서버에서 마지막으로 처리된 코드가 남는다. 이전 버전 복원이나 충돌 병합은 제공하지 않는다. 창 닫기 이벤트에서 마지막 요청이 끝난다고 보장할 수 없으므로, 사용자는 저장 완료 표시를 확인한 뒤 나가야 한다. 종료 직전 입력·오프라인 저장 보장은 이번 범위 밖이다.

## 오류·보관

| 상태·코드 | 의미 | 프론트 처리 |
| --- | --- | --- |
| 401 A001 | 토큰 없음·유효한 토큰의 회원이 없음 | 편집 내용 유지, 로그인 안내 |
| 401 기존 토큰 오류 코드 | 만료·잘못된 토큰 | 기존 로그인 오류 처리 |
| 404 C004 | 원본 문제 없음 | 저장 중단, 문제 삭제 안내 |
| 400 C001 | 잘못된 언어·문제 ID·JSON·code null 또는 길이 초과 | 입력·요청 수정 |

검증 오류는 기존 `{timestamp,status,code,message,errors}` 형식을 사용하며 입력값을 노출하지 않는다. JSON 파싱 오류도 기존 공통 오류 형식을 사용하되 코드가 포함될 수 있는 예외 메시지는 로그에 남기지 않는다.

문제 삭제 시 그 문제의 모든 작성 코드를 함께 삭제한다. 실행·제출 후에는 그대로 유지한다. 관리자 조회, 저장 이력, 별도 목록·삭제 API, 비회원 저장은 제공하지 않는다.
