# 68 GitHub 풀이 자동 저장 연동

이슈: https://github.com/DSM-Corte/Corte-BE/issues/68 / 기준 SHA: aefc8113b6f722f46157a1f6b447931d88466045

## 기능: GitHub 풀이 자동 저장 연동
- 목적: 로그인 사용자가 제출을 정답(모든 테스트케이스 통과)받으면 풀이를 본인 GitHub 레포에 자동 저장한다.
- API: 기존 제출 채점 확정(`JobStore.finish`, 판정 `ACCEPTED`)에서 `ProblemSolvedEvent`를 발행한다.
  연동 정보 저장은 `PUT /api/users/me/github`(ADMIN 전용, 본문 `installationId`(양수)·`owner`·`repo`(공백 불가)), 200 + 같은 세 값. 다시 호출하면 덮어쓴다.
- 데이터: `users`에 `github_installation_id`, `github_owner`, `github_repo` nullable 컬럼 추가(기존 행은 null, 스키마 영향 없음).
  세 값이 모두 있어야 연동으로 본다. 
- 규칙
  - 제출(`submission=true`)이고 작성자가 있고 GitHub 연동된 경우에만 발행한다. 비회원·실행 전용·미연동은 발행하지 않는다.
  - 같은 회원이 같은 문제를 이미 정답 처리받은 적이 있으면 발행하지 않는다(처음 정답 한 번만 저장).
  - 정답이 아닌 판정은 발행하지 않는다.
  - 발행은 `finish` 트랜잭션 안에서 하고, 커밋 후 기존 `@Async` 리스너가 저장한다.
  - 발행 중 예외는 ERROR 로그만 남기고 채점 결과 확정을 깨뜨리지 않는다.
- 오류: 새 오류 코드 없음. 본문 검증 실패 `C001`/400, 토큰 없음 `A001`/401, 관리자가 아니면 403.
  리뷰 지적: 임의 설치 ID 저장으로 타인 레포에 쓸 수 있어 ADMIN 전용으로 제한한다(사용자 셀프 연동은 GitHub OAuth 검증 후 별도 작업).
- 트랜잭션 / 동시성: 판정 갱신이 `RUNNING -> 판정` 조건부 원자적 업데이트라 같은 제출의 중복 finish는 한 번만 발행한다.
  같은 문제를 동시에 두 제출이 처음 맞히면 둘 다 발행될 수 있으나 같은 경로를 덮어쓰는 커밋이라 허용한다. / 성능: 정답 확정당 쿼리 2개 추가.
- 범위 밖: GitHub App 설치 콜백, 연동 해제, 재정답 시 덮어쓰기, 실패 재시도.
- 새 컨벤션: 없음.
- 테스트 대응(`JobStoreTests`): 정답 발행·중복 finish 1회 → `연동한_회원의_정답_제출은_풀이_저장_이벤트를_한번_발행한다`,
  오답·비회원·미연동 제외 → `정답이_아니거나_비회원이거나_연동하지_않은_제출은_이벤트를_발행하지_않는다`,
  재정답 제외 → `같은_문제를_다시_맞혀도_이벤트는_처음_한번만_발행한다`. 레드 증거: `User.linkGithub` 부재로 컴파일 실패.

- 테스트 대응(`UserControllerTests`): 저장 → `GitHub_연동_정보를_저장하면_연동된_회원이_된다`, 덮어쓰기 → `GitHub_연동_정보를_다시_저장하면_덮어쓴다`,
  검증 오류 → `GitHub_연동_정보가_비었거나_올바르지_않으면_400을_준다`, 권한 → `관리자가_아니면_GitHub_연동_정보를_저장할_수_없다`(레드: 일반 사용자도 200), 401 → `토큰_없이_GitHub_연동_정보를_저장하면_401을_준다`(필터가 이미 막아 레드 없음).
  레드 증거: 앞의 3개가 기능 없음으로 실패(13개 중 3개 실패).
