## 기능: 사용자 리뷰
- 용어: **요청자**(풀이를 올려 리뷰를 요청한 유저), **리뷰어**(요청자가 아닌 로그인 유저), **쓴 사람**(해당 코멘트·댓글·답글을 쓴 유저)
- 목적: 정답을 맞힌 요청자가 자기 풀이로 리뷰를 요청하면 리뷰어가 줄 코멘트와 전체 댓글로 리뷰한다.
  요청자는 코멘트 하나를 골라 적용한 코드를 보고 다시 풀어본다
- API (모두 로그인 필요, 목록은 page=0, size=20, 최대 100, ID 내림차순)

| API | 설명 | 성공 |
| --- | --- | --- |
| `POST /api/review-requests` | `{submissionId}`. 요청자 본인의 ACCEPTED 회원 제출만 가능 | 201 + Location |
| `GET /api/review-requests` | 목록(`problemId` 선택 필터). 닫히지 않은 요청 + 내가 요청한 요청 | 200 페이지 |
| `GET /api/review-requests/{id}` | 상세(`code`, `language`, `problemId`, 요청자, `closed`) | 200 |
| `POST /api/review-requests/{id}/close` | 요청자만. 되돌릴 수 없다 | 204 |
| `POST /api/review-requests/{id}/line-comments` | `{lineNumber, content, suggestedCode?}`. 리뷰어만 | 201 |
| `GET /api/review-requests/{id}/line-comments` | 전체 반환(요청당 상한 200개), 답글 포함 | 200 |
| `PATCH`·`DELETE /api/review-requests/{id}/line-comments/{commentId}` | 쓴 사람만 | 200·204 |
| `POST /api/review-requests/{id}/comments` | 전체 댓글. 리뷰어만 | 201 |
| `GET /api/review-requests/{id}/comments` | 페이징, 답글 포함 | 200 페이지 |
| `PATCH`·`DELETE /api/review-requests/{id}/comments/{commentId}` | 쓴 사람만 | 200·204 |
| `POST /api/review-requests/{id}/line-comments/{commentId}/replies`, `POST .../comments/{commentId}/replies` | 답글. 요청자·리뷰어 모두 | 201 |
| `PATCH`·`DELETE /api/review-requests/{id}/replies/{replyId}` | 쓴 사람만 | 200·204 |
| `POST /api/review-requests/{id}/apply` | `{lineCommentIds:[…]}`. 요청자만. 계산만 하고 저장하지 않는다 | 200 `{code}` |

- 권한: 줄 코멘트·전체 댓글 작성은 리뷰어만, 답글은 누구나, 적용·닫기는 요청자만, 수정·삭제는 쓴 사람만
- 데이터 (신규 테이블 4개, 기존 데이터 영향 없음)
  - `ReviewRequest`(`review_requests`): submission(`JudgeJob`, 유니크 `uk_review_requests_submission_id`), requester, problem, language, `code` 스냅샷, `closed`, createdAt, updatedAt
  - `LineComment`(`line_comments`): 요청, 쓴 사람, lineNumber(1 이상, 코드 줄 수 이하), content(마크다운), suggestedCode(nullable)
  - `ReviewComment`(`review_comments`): 요청, 쓴 사람, content
  - `ReviewReply`(`review_replies`): 요청, 부모(줄 코멘트 또는 전체 댓글), 쓴 사람, content. 1단계만
- 규칙
  - 적용: `lineCommentIds`가 정확히 1개(0개·2개 이상은 400). 그 코멘트의 `suggestedCode`로 해당 줄을 대체한 전체 코드를 응답. 제안 코드가 없으면 409. 횟수 제한 없음
  - 줄 수는 마지막 줄바꿈 뒤의 빈 줄을 세지 않는다. CRLF 줄의 `\r`은 유지한다
  - 제출당 리뷰 요청 1개
  - 닫힌 요청: 요청자만 조회할 수 있다(목록은 요청자 본인 것만 포함, 리뷰어는 상세·하위 조회 모두 404). 요청자도 작성·수정·삭제는 409, 조회와 적용은 가능
  - 코멘트·댓글을 지우면 그 답글도 함께 지운다
  - 검사 순서: 요청 접근(404) → 역할·쓴 사람(403) → 닫힘(409) → 입력·상태. 닫힌 요청에서 남의 것을 고치면 409가 아니라 403이다
  - 코드 블록은 마크다운으로 저장하고 렌더링은 프론트가 맡는다
- 오류(접두사 `R`): 요청 없음/닫힌 요청에 리뷰어 접근 R001 404, 코멘트·댓글·답글 없음 R002 404, 본인 제출 아님 R003 403,
  제출 없음 R004 404, 정답 아님 R005 409, 중복 요청 R006 409, 요청자가 코멘트·댓글 작성 R007 403,
  요청자 아님(닫기·적용) R008 403, 쓴 사람 아님 R009 403, 닫힌 요청 R010 409, 줄 번호 범위 R011 400,
  적용 선택 개수 R012 400, 제안 코드 없음 R013 409, 줄 코멘트 상한 초과 R014 409
- 트랜잭션: 쓰기 메서드마다 하나 / 동시성: `submission_id` 유니크 제약(중복 요청), 닫기는 조건부 UPDATE(`closed=false`일 때만).
  줄 코멘트 상한과 닫힘 확인은 사전 조회라 동시 요청에서 약간 어긋날 수 있다(허용)
- 성능: 목록은 projection + count 쿼리, 답글은 부모 ID 목록으로 한 번에 조회, 줄 코멘트는 상한 200개
- 기술 선택: 현재 스택(JPA, MySQL)
- 범위 밖: AI 리뷰, 알림, 좋아요, 점수, 여러 줄 코멘트, 요청 삭제, 닫은 요청 다시 열기, 적용 코드 저장
- 새 컨벤션: 오류 코드 접두사 `R`(사용자 리뷰) 추가
