# 서버 시간대 고정 (#86)

기준 SHA: `e12df7e`

## 기능: 서버 기본 시간대를 한국 시간으로 고정
- 목적: 서버를 어디서 실행하든(Docker는 UTC, 개발 PC는 한국) 사용자가 제출 시간·작성 시간을 실제 한국 시간으로 본다
- API: 변경 없음. 시간대 없는 시각(`LocalDateTime`) 응답이 한국 시간이 된다
- 데이터: 스키마 변경 없음. 수정 전 UTC 환경에서 저장된 기존 시각은 변환하지 않는다(팀 결정: 영향을 적고 진행). 기존 데이터에 생기는 영향:
  - 기존 시각 응답(`createdAt` 등)은 지금처럼 9시간 이르게 보인다
  - 잔디·연속 풀이·리더보드 연속 일수는 기존 시각을 한국 시간으로 읽는다. 그래서 한국 시간 0시~9시에 맞힌 기존 기록은 전날로 옮겨지고, 연속 풀이가 끊기거나 잔디 칸이 바뀔 수 있다. 조회 범위 경계도 기존 데이터에서는 9시간 어긋난다
  - 배포 직전에 만든 비회원 실행 작업은 만료 시각(`expiresAt`)이 UTC 기준이라 배포 직후 바로 만료될 수 있다
  - 수정 뒤 새로 저장되는 시각에는 위 영향이 없다
- 규칙: 애플리케이션 시작(`main`) 시 JVM 기본 시간대를 `Asia/Seoul`로 정한다. 잔디·연속 풀이처럼 기본 시간대를 한국 시간으로 바꾸던 계산은 새 데이터에서 결과가 같다(기존 데이터는 위 데이터 항목 참고)
- 오류: 없음
- 트랜잭션 / 동시성: 없음 / 성능: 없음
- 범위 밖: 기존 데이터 변환, 응답에 시간대 표기 추가, `GrassService`·`LeaderboardService`의 "서버 시간대(보통 UTC)" 주석 갱신
- 재현 조건: 서버 JVM 시간대가 UTC일 때 13:52(KST)에 제출하면 `createdAt`이 04:52로 응답된다
