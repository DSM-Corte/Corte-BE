# 테마 동시 변경 시 한쪽 유실

- 이슈: #70
- 기준 SHA: aefc8113b6f722f46157a1f6b447931d88466045

## 기능: 테마 동시 변경 시 한쪽 유실 (버그 수정)
- 목적: 회원이 모드와 강조색을 빠르게 연달아 바꿔도 두 변경이 모두 저장되게 한다
- 재현: 같은 회원으로 `PATCH /api/users/me/theme`에 `{"mode":"DARK"}`와 `{"color":"PINK"}`를 동시에 보내면
  `DARK/BLUE`나 `LIGHT/PINK`로 저장된다(로컬 MySQL에서 20번 중 20번)
- 원인: 두 요청이 같은 회원 행을 읽은 뒤 각자 한 칸만 바꾸는데, 저장할 때 `users`의 모든 컬럼을 다시 쓴다. 나중에 저장된 요청이 다른 요청의 변경을 이전 값으로 덮어쓴다
- API: 변경 없음
- 데이터: DB 변경 없음. `User` 저장 시 바뀐 컬럼만 UPDATE한다(`@DynamicUpdate`)
- 규칙
  - 모드와 강조색을 서로 다른 요청으로 동시에 바꾸면 둘 다 남는다
  - 같은 칸을 동시에 바꾸면 나중에 저장된 값이 남는다(기존과 같다)
- 오류: 변경 없음
- 트랜잭션: 변경 없음 / 동시성: 바뀐 컬럼만 UPDATE해 서로 다른 칸의 동시 변경을 보존한다. 같은 행 UPDATE는 DB 행 잠금으로 차례로 실행된다 / 성능: 변경 없음
- 범위 밖: 같은 칸 동시 변경의 순서 보장, 프론트 요청 순서(프론트 이슈에서 처리)

## 검증 기록
- 빌드: `./gradlew build` 종료 코드 0, 테스트 378개 실패 0 (`f704049`)
- 테스트 무결성: 삭제·건너뛰기·약해진 단언 없음(추가만 있음)
- 되돌림 검사: `src/main`만 되돌리면 `ThemeConcurrencyTests` 종료 코드 1로 실패
- 실행 검증(MySQL 8.4, `SERVER_PORT=8081`): 같은 회원으로 `{"mode":"DARK"}`와 `{"color":"PINK"}`를 동시에 보내는 실험 20번
  - 수정 전 20번 중 20번 한쪽 유실 → 수정 후 0번
  - 단독 변경 200, 빈 본문 400 `C001`, 가입·로그인 정상
- 독립 리뷰(서브에이전트)와 처리
  - 명세 충족, 테스트 속이기 없음, 다른 회원 저장·잠금 경로(가입 INSERT, `findLockedById`)에 영향 없음
  - 수정 후 MySQL 결과 기록 필요 → 위 실행 검증으로 기록
  - PATCH 응답에 상대 칸의 이전 값이 실릴 수 있다 → 프론트는 PATCH 응답을 화면 상태에 쓰지 않아 지금은 영향 없음. 고치지 않음
  - 테스트 클래스 이름이 `<대상>Tests` 규칙과 다름 → 기존 `ThemeServiceTests`는 Mockito 단위 테스트라 통합 테스트를 넣을 수 없고, `CodeDraftConcurrencyTests` 선례를 따랐다
  - 같은 칸을 읽고 계산해서 쓰는 로직이 생기면 `@DynamicUpdate`로 막히지 않는다 → 지금은 해당 코드 없음
